# 中文输出规范

本模块适用于回复、文档、README、报告、表格和代码说明中的中文内容。逐字引用、
用户明确要求、项目术语表和更深层的项目指令优先。下列改写示例只用于校准表达，
不构成当前任务的事实、数值或结论。

## 标准术语

- 已有通用说法或目标领域既定术语时，直接采用稳定用法，不另造表述。
- 判断中文技术术语时，以目标领域的中文论文、官方文档和技术社区用法为主要
  依据。源语言中的常用程度只作背景信息。
- 单个偶发译例只作弱证据。缺少稳定译法时，根据术语在当前文本中的功能改写，
  使中文读者无需回溯原文即可理解。
- 功能性改写可能丢失与原文的对应关系时，在首次出现处附英文原词。
- 逐字引用中文材料时保留原词；逐字引用英文材料时保留英文。

常见校准示例：

| 待改写表达 | 推荐表达 |
| --- | --- |
| 超长度 | 截断 |
| 超不超长度 | 是否触及长度上限 |
| Ray 的端口会跟自己撞 | 多个任务的 Ray 抢占同一端口 |
| 臂 | 按功能写为方案、实验组、实验设置、系统配置或方法变体 |
| 只看长度那条线 | 长度启发式基线 |
| 刷奖励 | 奖励被优化但评测指标未改善 |
| 存档 | `checkpoint` |

在 LLM、机器学习与系统论文中，`experimental arm` 或 `study arm` 通常按具体
功能写为“实验组”“对照组”“实验设置”“系统配置”“方法变体”或“方案”。
“臂”保留于多臂老虎机、临床试验既定术语或原文引用。

## 直接、书面和非拟人表达

- 不使用需要读者推断指代对象的比喻。直接说明对象、动作、条件、变量和结果。
- 不使用口语词、评价性绰号或含义依赖语境的简写。
- 不把模型、指标、训练过程、系统或数据写成具有人类意图和行为的主体。
- 避免先否定前项、再强调后项的对照句式，也避免通过否定他人或已有观点强化
  结论。直接陈述检查结果、差异来源和适用范围。
- 删除没有新增事实、条件或推理作用的过渡句。
- 保留原文中的必要限定，避免为了表达流畅扩大结论范围。

比喻和含混表述的校准示例：

| 待改写表达 | 推荐表达 |
| --- | --- |
| 血统 | 基座来源 |
| 8 个不同血统 | 8 个不同基座的模型 |
| 那是尺寸差异，不是血统差异 | 原有区间由 Qwen 的 14B、32B、72B 构成，差异来自参数量而非基座 |
| 已经吃掉一半空间 | 已覆盖一半区间 |
| 变成了一个认题目的检索器 | 退化为问题识别，与学习价值无关 |
| 挑出来的题目看上去健康得多 | 选中问题的截断比例更低 |
| 误差范围还盖着基准线 | 置信区间与基线重叠 |

对照句式的校准示例：

| 待改写表达 | 推荐表达 |
| --- | --- |
| 梯度对齐：是噪声，不是信号 | 梯度对齐：三项检查结果均在噪声范围内 |
| 我们买到了血统上的多样性，但没有买到能力上的多样性 | 新增模型覆盖了更多基座，但正确率均低于原有区间下界 |
| 考法和用法对不上 | 评测口径为成对比较，与实际使用方式不一致 |
| 稳定是靠粗糙换来的 | 取值数量少的指标重合率高 |
| 越稳定的指标越挑不出东西，越挑得出东西的指标越不稳定 | 重合率与取值数量呈反向关系 |

口语表达的校准示例：

| 待改写表达 | 推荐表达 |
| --- | --- |
| 赢得很干脆 | 报告差值；例如在数据支持时写“差值为 0.030” |
| 测得更准 / 测得更糙 | 估计精度更高 / 更低 |
| 可选的余地很小 | 候选范围小 |
| 基本上等于抓阄 | 接近随机选取 |
| 本来就分不出高下 | 真实差距低于可分辨范围 |
| 白跑 / 白占 | 无效运行 / 空占 |
| 不是白捡的 | 报告资源成本；例如在数据支持时写“需要 79 GPU·小时” |
| 一个致命问题 | 主要问题 |
| 有事后找补的嫌疑 | 该切分方式在观察结果之后确定 |
| 原因不复杂 | 删除 |
| 既然预测这条路走不通，那就退一步 | 删除，直接进入实验设置 |

拟人表述的校准示例：

| 待改写表达 | 推荐表达 |
| --- | --- |
| 天生需要几百到上千次采样 | 该信号所需的采样量为几百到上千次 |
| 一旦超就制造出参差 | 截断发生时会增大奖励方差 |
| 24 步训练只挪动 0.05 | 24 步训练后正确率变化为 0.05 |
| 超得越彻底反而越稳定 | 截断率越高，奖励方差越低 |
| 回答内容本身的好坏参差 | 答案质量存在差异 |

## 中性名称和一致状态

- 表头、分类名和章节状态使用中性名词，例如“问题”“现象”“影响”“结果”。
- 同一文档中的状态标签保持一致。已经采用“已完成”“已确认”“未达到基线”
  和“结论待定”时，后文继续使用这组标签。
- 避免把“做通了”“意外发现”“需要修”“没有买到想要的”等口语表达混入
  正式状态标签。

常见校准示例：

| 待改写表达 | 推荐表达 |
| --- | --- |
| 坑 / 代价和教训 | 问题 / 影响 |
| 把握 | 确认程度 |
| 怎么做的 | 实验设置 |
| 重挑一次还剩多少重合 | 重采样后的重合率 |
| 有几种不同取值 | 取值数量 |
| 还在跑的 | 进行中 |
| 一个必须关掉的开关 | 需要关闭的过滤器 |

## 事实边界和未确认原因

- 原因尚未查明时直接写“原因未查明”。
- 前文已经标记原因未查明时，后文不补充未经验证的因果解释。
- 观察到相关性但尚未完成验证时，明确写出待验证关系。例如，将“这可能也解释
  了前文那个现象”改为“该现象与截断的关系尚未验证”。
- 后续证据确认原因时，说明新增证据、适用范围和状态变化。

## 表格条目

- 表格条目只需完整表达所在字段的事实或状态，不要求每条都包含数字、比较或
  结论。
- 不为追求形式一致而补充材料未支持的关系。例如，“对照组为随机选取的 32 个
  问题”已经完整时，保留该句即可。
- 数字、比较和结论只在来源材料、计算或实验结果能够支持时加入。

## 完成检查

- 术语是否采用目标领域稳定用法，未归一化术语是否已经按功能改写？
- 每个代词、简称和比喻是否都有直接、无需推断的替代表达？
- 表头、分类名和状态标签是否中性且一致？
- 原因、相关性和结论是否与现有证据范围一致？
- 是否仍有口语、拟人、先否定后强调的对照句式或无信息过渡句？
- 示例中的名称、数字和结论是否仅在当前材料支持时使用？
