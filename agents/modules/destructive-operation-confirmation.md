# 高危操作确认

可能造成数据丢失、难以恢复的状态变化或大范围覆盖时，在执行前取得用户的二次
确认。此要求同样适用于用户在最初请求中直接提出的高危操作。

高危操作包括：

- 递归删除、整目录删除和大范围文件清理；
- 会丢弃未提交、未备份或难以恢复内容的覆盖性复制或移动，以及影响范围难以
  准确审查的大范围批量替换；
- 改写共享或非当前任务 Git 历史、强制推送和删除远程分支或标签；
- 删除数据库、云资源、远程数据或其他难以恢复的持久状态；
- 其他可能超出已明确目标或显著扩大影响范围的不可逆操作。

请求确认前：

1. 通过只读检查解析准确目标。
2. 列出受影响的绝对本地路径或准确的远程资源标识。
3. 说明操作类型、影响范围、主要风险、恢复方式和可用备份。
4. 给出准备执行的具体命令或等价操作。

用户确认前只进行只读检查和风险说明。确认仅覆盖已经列出的目标和操作；目标、
命令或影响范围发生实质变化时重新确认。

不要将 `/`、用户主目录、工作区根目录、未解析的变量或宽泛通配符直接作为递归
破坏性操作的目标。先将目标解析为准确、显式的路径或资源标识。

可行时优先采用可恢复操作。完成实质性删除或覆盖后，简要报告实际影响以及恢复
位置或恢复限制。
