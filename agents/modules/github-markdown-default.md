# GitHub Markdown 默认格式

创建或实质改写任何 `.md` 文件时，默认以 GitHub Flavored Markdown（GFM）为
核心，并按需使用 GitHub 支持的扩展。

## 适用边界

- 用户明确要求、当前目录下更深层的 `AGENTS.md`、项目贡献规范、文档模板、
  Markdown lint 配置和目标发布平台规则优先。
- 编辑已有文件前先检查其现有结构和附近文档的写法。局部修改延续当前风格，
  避免产生与任务无关的整文件格式变化。
- 保留目标工具所需的 YAML front matter、指令注释和扩展语法，例如 Marp、
  MkDocs、Hugo 或 Pandoc 的项目约定。

## 基础结构

- 独立文档使用一个说明主题的一级标题，并按层级递进组织后续标题。
- 标题、段落、列表、表格、引用和围栏代码块之间保留空行。
- 无序列表统一使用 `-`。有先后关系的步骤使用有序列表；可执行清单使用
  `- [ ]` 和 `- [x]`。
- 行内代码、命令、文件名、路径、配置键和标识符使用反引号。
- 多行代码或终端输出使用围栏代码块；已知语言或数据格式时标注语言。
- 表格用于多项精确映射或比较。保持单元格简洁，并转义内容中的竖线。
- 链接文字说明目标内容。仓库内文档和资源优先使用相对链接，图片提供有意义的
  替代文本。

## GitHub 扩展

- 目标渲染器支持 GitHub Alert 时，仅将其用于会影响任务完成、正确性或安全性的
  提示，并控制使用数量。
- 折叠区块用于补充材料、较长日志或次要细节，正文保留完成任务所需的信息。
- 原生 Markdown 能清晰表达时优先使用原生语法。使用 HTML 前确认 GitHub 和目标
  文档工具都支持该元素；不依赖自定义 CSS 或脚本。

## 数学公式

- 行内数学公式使用 `$...$`。
- 块级数学公式使用独立的 `$$` 分隔行：

  ```markdown
  $$
  f(x) = x^2
  $$
  ```

- 块级公式不使用 `\[` 和 `\]` 分隔符。
- 公式与 Markdown 语法冲突且目标渲染器支持时，可使用 GitHub 的行内转义形式或
  `math` 围栏代码块。

## 完成检查

- 检查标题层级与锚点、列表缩进、围栏闭合、表格列数、相对链接和图片路径。
- 含数学公式时检查定界符配对和 GitHub 渲染结果。
- 项目提供 Markdown 检查器或文档预览命令时，运行与本次改动相关的最小验证集。
