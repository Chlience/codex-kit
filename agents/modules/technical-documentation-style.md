# 技术文档基础约束

本模块适用于 README、教程、操作指南、概念说明、API 与命令参考、运行手册、
故障排查和安全说明。用户要求、项目规范、领域标准、接口定义、语言专项规则和发布
平台要求优先。

## Skill 触发

- 可用技能中包含 `technical-documentation-writing` 时，创建、实质改写、重组或完整
  审查技术文档必须使用该 Skill。
- 局部拼写、标点、链接或格式修订可以直接完成，但必须保持现有技术含义和文档结构。
- Skill 不可用时执行下列基础约束，并明确不能使用完整工作流的验证范围。

## 基础约束

- 开始前确认目标读者、任务或理解目标、适用版本、前置条件和可观察完成结果。
- 一个概念使用一个稳定术语。优先采用项目术语表、公开接口和目标领域正式名称。
- 每个句子表达一个主要陈述或一项指令。默认使用主动语态并明确执行主体。
- 操作步骤使用祈使句，一步只包含一项主要操作；先写条件和环境，再写操作及结果。
- 原因、性能、兼容性和安全结论必须处于现有证据范围内。原因未查明时直接写
  “原因未查明”。
- 命令、代码、配置和示例必须与正文目标一致，不包含真实凭据、个人数据或生产资源
  标识符。
- 将安全说明放在危险操作之前，使用项目或领域批准的风险等级，并说明潜在结果。
- 链接使用描述性文字；图片提供替代文本；不只依赖颜色、位置、方向或图标传达信息。
- 检查链接、锚点、命令、代码、配置、界面标签和预期输出。不能验证时列出具体范围
  和原因。
