# 中文数学与机器学习技术研究写作

迁移公开技术文章中可复核的问题解决与表达机制。只迁移功能结构；禁止冒充苏剑林、复用标志性措辞、伪造署名或暗示作者认可。

## 确定任务

先选择一个主接口：

| 接口 | 选择条件 | 主要交付物 |
|---|---|---|
| `explore` | 问题仍需重述、推导、比较、反例、实验或实现检查 | 精确问题、探索路线、局部检查、范围明确的结果 |
| `explain` | 需要解释论文、方法、模型、公式或技术主张 | 最小准备、机制重建、证据与限制、归因清楚的解释 |
| `draft` | 已有研究笔记、结果、论证或来源材料 | 连贯的中文技术文章 |
| `revise` | 已有中文数学或机器学习技术草稿 | 简短诊断、修订稿、实质改动、未决项 |

同时确定目标读者、默认先修知识、期望篇幅、可用来源，以及数学、实验、代码或实现检查条件。缺失信息会实质改变技术结果时，只询问一个最关键的问题；其余情况写明假设后继续。

任务超出中文数学、机器学习及相邻技术研究写作时，说明语料依据的范围限制，再采用一般分析方法完成可处理部分。

## 遵循质量顺序

按以下顺序处理冲突：

1. 保证数学、事实和代码语义正确；
2. 让假设、来源、贡献主体和不确定性可追溯；
3. 让关键解释可以复算、复查或复现；
4. 在前三项满足后采用本 skill 的推理和行文机制。

材料不足时，给出已验证的最强局部结果，并定位缺失的来源、假设、等式、实验或实现步骤。不得编造引用、推导、实验、代码运行或数值结果。

## 执行共享流程

1. 把主题收缩为可检查的问题、差异或设计目标，写出对象、条件、未知量与完成判据。
2. 进行早期来源检查，确认已知结果、常见基线、贡献主体与潜在重合。无法访问来源时标出具体未核实主张。
3. 只引入下一步需要的定义、符号、假设和基线。
4. 默认尝试表示或观察对象转换：寻找等价形式、参数化、几何或概率视角、退化情形、资源模型或接口分解。要求转换产生新的可计算量、可证明结构、可实现对象或可核验预测。
5. 默认把目标性质、约束、误差、资源和失败判据写成构造条件，让这些条件决定公式、算法、实验设置或实现方案。
6. 为每项关键主张安排匹配的检查：数学命题用证明、反例或边界分析；计算性质用数值核对；经验主张用受控实验；工程行为用实现测试和资源测量。
7. 只在存在可定位反馈时启用失败—修订链，保留原假设、反馈与对应改动。事前风险只写成预防性判断。
8. 进行后期来源检查，复核相关工作、原创性表述、独立重复发现、遗漏与引用边界。
9. 在结论附近标出假设、证据类型、适用范围、置信度和未验证项。

需要展开第 4—8 步时，读取 [reasoning-protocol.md](references/reasoning-protocol.md)。

## 按接口交付

### `explore`

- 输出精确问题、已知条件、未知量和成功判据。
- 分开记录来源已知内容、当前独立推导和猜测。
- 展开有推进作用的表示转换与约束构造，必要时处理特例或近似。
- 记录实际检查过的路线、反馈、修订与仍待执行的检查。
- 给出局部结论、成立范围、剩余问题；仅在用户要求时附文章稿。

### `explain`

- 先确认原始来源及贡献主体，再从该工作解决的问题进入。
- 提供理解核心机制所需的最小准备。
- 重建表示转换、目标约束、关键推导及检查依据。
- 在关键公式前说明用途，公式后解释结构、含义、限制和下一步作用。
- 分开陈述原来源主张、他人的重构或评价、当前任务的独立推导和用户判断。
- 汇总假设、实验、限制与独立复查入口。

### `draft`

- 先建立事实、推导、实验和来源台账。
- 在开篇尽早提出具体问题，让段落和小节跟随推理任务。
- 把定义、公式、图表和代码放在承担实际作用的位置。
- 让证据与相邻结论对应，区分证明、实验、观察、解释性假说和待验证方向。
- 依据体裁选择问句、系列回顾与结尾深度。
- 完稿后执行正确性、归因、可检查性和反模仿检查。

### `revise`

- 先给出按质量顺序排列的简短诊断。
- 优先修复事实、公式、代码语义、来源与结论范围。
- 重排问题、表示转换、约束、检查和结论之间的依赖。
- 保留用户的有效发现、真实经历和个人声音。
- 删除无功能问句、装饰性类比、断开的公式与来源含混段落。
- 返回修订稿、实质技术改动和仍待解决的问题。

处理完整文章或行文修订时，读取 [writing-patterns.md](references/writing-patterns.md)。

## 启用条件机制

- **特例或近似**：只在简化能产生一般性洞见时使用；返回一般范围时写清条件、误差、代价或无法推广的位置。
- **失败反馈**：只在实际异常、反例、实验或实现反馈改变路线时使用；禁止补写未发生的研究经历。
- **系列状态恢复**：只在当前子问题依赖前文时使用；恢复必要结论、条件与未决项，再说明本篇增量。
- **功能性问句**：只用于触发定义、分支、反例、检查或边界。
- **完整结尾**：用于长篇、复杂推导或阶段复盘；短证明和实现记录可在结果与适用条件处结束。

## 管理证据与身份边界

涉及外部主张、论文解读、团队工作、优先权或人物风格要求时，读取 [evidence-and-boundaries.md](references/evidence-and-boundaries.md)。

至少区分原论文或外部方法作者、博客作者的重构或评价、团队与合作者、当前任务的独立推导、用户提供内容和无法确认的贡献。首次看到某种形式不能证明原创优先权。

用户要求模仿人物时，把需求转换为问题驱动、表示转换、约束构造、公式解释、反馈修订或系列状态恢复等功能目标，并明确转换后的范围。不得以苏剑林第一人称写作，不得复制其标志性标题、短语、笑点、个人故事或固定节奏，不得把生成内容归为其文章或观点。

## 完成前检查

- 每项关键结论能否回指推导、来源或检查？
- 表示转换是否改变了后续操作？
- 方案是否能回指具体目标、约束、误差或成本？
- 公式前后是否分别交代用途与结构性含义？
- 证明、实验、观察、猜测和未验证项是否区分？
- 原论文、博客重构、团队工作、外部提示、当前推导和用户内容是否分开归因？
- 结论是否覆盖正文发现的条件、反例和验证缺口？
- 是否保留用户声音，并移除身份冒充、标志性措辞复用和虚假归因？
