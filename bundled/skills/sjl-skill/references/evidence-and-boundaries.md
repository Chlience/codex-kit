## 区分主张状态

对每项关键主张标记以下状态之一：

| 状态 | 含义 | 推荐写法 |
|---|---|---|
| 来源事实 | 一手来源明确陈述或报告 | “原文给出……”，附来源与范围 |
| 独立重构 | 当前作者复算、改写或重新连接已有结果 | “这里从……重新推出……”，保留原始来源 |
| 当前推导 | 在本次任务中由已写条件推出 | 展示关键步骤与检查 |
| 实验观察 | 来自明确实验或实现 | 给出设置、结果、主体与限制 |
| 解释性假说 | 能解释现象，证据尚不足 | 明确写为假说并列验证方式 |
| 用户判断 | 用户提供的观点或结论 | 保留来源身份，必要时核查 |
| 未核实 | 来源不可访问或证据缺失 | 指明待核实的具体内容 |

同一段混合多个状态时拆成多个主张，或明确标出各自边界。

## 记录贡献主体

为外部技术主张记录：

- **来源**：论文、网页、代码、实验日志或用户材料；
- **行动者**：原论文作者、博客作者、团队、具名合作者、外部提示者、当前推导者、用户或无法确认；
- **贡献类别**：原创提案、独立重构、统一解释、局部修改、论文解读、实现、实验、综述、转载或翻译；
- **确定性**：已核实、部分核实、推断或未核实。

采用以下归因规则：

1. 原论文的方法、证明、实验和结论持续归原论文作者。
2. 博客作者完成的复推、等价连接、补充检查、实现或评价单独归属。
3. 以“我们”描述的设计、训练或实验按团队成果处理，除非来源明确列出个人分工。
4. 合作者、社群成员或外部工具提供的证明、提示和结果保留原贡献主体。
5. 当前任务新完成的推导归当前任务，不能回写为来源作者的原创。
6. 首次看到某种形式只能证明接触顺序，不能证明原创优先权。

涉及原创性、首次、独立发现和方法史时，优先查一手来源。证据不足时降低表述强度。

## 校准结论强度

把证据—结论一致性作为强制质量护栏。这项规则服务技术可靠性，并独立于任何单一语料的表达习惯；缺少系统证据时，不把某项做法概括为任何作者始终遵循的习惯。

在相关结论附近标出：

- 数学假设和适用条件；
- 证据类型：证明、数值核对、实验、实现、来源报告或猜测；
- 数据、任务、模型、规模、版本与环境；
- 已知反例、失败区间和验证缺口；
- 可以支持的最强结论及置信度。

常见校准方式：

- 从“证明了普遍有效”改为“在给定假设下成立”；
- 从“实验表明一般规律”改为“在所述任务和设置中观察到”；
- 从“该机制导致结果”改为“结果与该解释一致，仍需区分其他解释”；
- 从“已实现”改为“给出实现方案，尚未运行验证”。

礼貌性保留词不能替代具体范围。直接说明哪个条件、数据或检查仍缺失。

## 执行来源检查

早期检查用于确定已知结果、基线与贡献边界；后期检查用于核对推导后出现的新关键词、相关工作和原创性表述。

优先顺序：

1. 原论文、正式文档、官方代码或数据；
2. 作者公开说明、可复现实验和版本记录；
3. 高质量二手解释；
4. 无法追溯出处的转述，只作线索。

记录访问日期和版本，尤其处理软件、模型、排行榜或持续更新的结论。来源无法访问时，不用其他文本替它确认原文内容。

引用原文只服务来源核对或必要的措辞分析，保持短小并明确标注。主体写作使用独立表达。

## 遵守反模仿边界

本 skill 迁移的是可检查的功能机制：

- 具体问题与完成判据；
- 表示或观察对象转换；
- 由目标、约束和误差构造；
- 与主张匹配的检查；
- 真实反馈推动修订；
- 有依赖时恢复系列状态；
- 公式前说明用途、公式后解释结构；
- 就近标注范围和不确定性。

不得执行以下动作：

- 以苏剑林第一人称发言或编写其可能说过的话；
- 复用标志性标题、固定短语、惯用笑点、个人故事或独特段落节奏；
- 把生成文本标为仿写、作者文章、作者观点或作者认可；
- 将原论文、团队、合作者、外部提示或当前任务的贡献转记给作者个人；
- 为追求表面相似增加无功能问句、语气词、标点或固定结尾。

用户提出人物模仿要求时，把要求转换为可核验的功能目标，并说明输出采用功能性适配。修改用户稿件时优先保留用户自身语气。

## 处理信息不足

| 情况 | 处理 |
|---|---|
| 原始来源缺失 | 标出未核实主张，只处理可验证部分 |
| 推导无法闭合 | 给出最强局部结果，定位缺口所在假设、等式或步骤 |
| 无法运行实验或代码 | 写成待执行检查，列出设置与成功判据 |
| 来源互相冲突 | 并列冲突、版本和证据，避免强行合并 |
| 贡献主体不清 | 标记“无法确认”，避免推定个人原创 |
| 只有弱证据 | 使用局部、条件或待验证表述 |
| 任务超出适用领域 | 采用一般方法，取消语料支持声明 |
