## 选择文章骨架

默认采用问题依赖顺序：

```text
具体问题与判据
  → 必要设定
  → 当前表示的障碍
  → 表示转换
  → 目标与约束
  → 构造或推导
  → 检查
  → 结果、范围与未决项
```

按体裁调整：

| 体裁 | 建议骨架 |
|---|---|
| 数学推导 | 命题与条件 → 关键变换 → 推导 → 边界或第二检查 → 结论 |
| 机制解释 | 现象 → 基线解释 → 新视角 → 可核验后果 → 证据与限制 |
| 论文解读 | 原问题 → 最小基线 → 原方法 → 当前重构或检查 → 实验与限制 |
| 实验研究 | 设计目标 → 变量与对照 → 结果 → 异常与修订 → 适用范围 |
| 工程记录 | 输入与约束 → 接口设计 → 故障检查 → 修订 → 可运行结果 |
| 系列续篇 | 必要前文状态 → 当前未决项 → 本篇增量 → 检查与新边界 |

文章顺序应反映读者理解依赖。不得为了制造探索感而改写真实研究历史。

## 组织开头与小节

开头尽早提供：

- 当前处理的具体问题、异常、缺口或设计目标；
- 判断完成与否的标准；
- 文章覆盖范围及必要先修；
- 有助于阅读的局部结论，可按任务选择是否提前说明。

用小节标记当前对象或推理任务，例如“设定”“转换”“构造”“检查”“边界”。按模型、数据集、实现模块或方案分组也可采用，只需让读者识别当前位置。

只在下一步需要时引入定义、符号、假设和组件职责。比较型文章允许先完整建立必要基线。删除后文未使用的预备知识。

## 解释公式与技术载体

在关键公式前说明：

- 本步准备计算或证明什么；
- 公式承担哪个约束或局部障碍；
- 使用哪些条件与记号。

在公式后解释：

- 变量角色、矩阵形状、概率意义或几何结构；
- 极限行为、误差、复杂度或实现后果；
- 该结构怎样引出下一项构造、检查或边界。

避免逐字复述公式、连续堆叠缺少连接的等式，以及使用“显然”跳过关键推理。

图表、代码和伪代码也遵循相同原则：先说明要回答的问题，再解释结果或接口如何改变后续判断。

Markdown 中的块级数学公式使用独立的 `$$` 分隔行，行内公式使用 `$...$`。

## 安排检查与修订

让证据紧邻它支撑的主张：

- 证明后说明依赖的假设与覆盖范围；
- 实验后说明对照、规模、随机性和可推广边界；
- 数值结果后说明精度、极端输入和稳定性；
- 实现后说明环境、故障输入与资源代价；
- 引用后说明来源贡献与当前文章增加的内容。

出现真实失败时，保留“预期—反馈—修改”的对应关系。只保留影响当前路线的信息。风险预判写为设计依据，不使用失败完成时态。

## 使用问句、回顾与结尾

### 问句

只让问句承担以下功能之一：

- 收缩为可检验问题；
- 触发定义、分支、反例或实验；
- 预判范围、变量控制或实现成本方面的异议；
- 从来源解读切换到当前作者的检查与评价。

陈述句能够更直接推进时，使用陈述句。问句频率不作为质量指标。

### 系列回顾

当前推理依赖前文时，压缩恢复必要公式、条件、结论和未决项，并说明本篇增量。背景介绍、系列编号或链接列表无需包装成状态恢复。

### 结尾

依据文章长度和复杂度选择：

- 长篇、复杂推导或阶段复盘：恢复问题、关键转换、主要结果、范围和剩余问题；
- 短证明或实现记录：在最终结果及必要适用条件处结束；
- 强结论：就近保留关键条件、反例和验证缺口，即使结尾较短。

完整结尾属于可选体裁策略。禁止把固定收束形式当成个人风格模板。

## 起草与修订清单

### 起草

1. 用一句可检验的问题、异常或目标建立判据。
2. 只引入后文承担作用的设定。
3. 解释表示转换怎样改变可处理对象。
4. 让方案逐项回指目标、约束、误差或成本。
5. 让公式前的用途和公式后的结构解释形成连续推理。
6. 为主张选择匹配检查并标明证据主体。
7. 只记录真实的反馈—修订链。
8. 在结论附近标出证据类型、范围和未验证项。

### 修订

1. 修复事实、公式、代码和来源错误。
2. 把宽泛主题改成可检查的问题。
3. 删除未产生后续作用的符号替换、类比和预备知识。
4. 补全方案与目标、约束、误差或成本的连接。
5. 补充关键公式的用途、含义和下一步作用。
6. 删除装饰性问句、身份模仿和标志性措辞复用。
7. 分开归因原论文、重构、团队工作、外部提示和当前推导。
8. 校准结论范围，列出仍需验证的实质问题。
